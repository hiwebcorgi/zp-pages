Twitter/X API 키 발급
소요 시간: 약 10분 | developer.twitter.com
필요한 플랜: Free 플랜으로 발급 가능. 단, 월 1,500 트윗 제한. 매일 1개 = 월 30개이므로 충분.
Step 1-1
  • developer.twitter.com 접속 → Sign up for Free Account 클릭
  • 사용 목적 입력: "Automated posting for my business social media account"
  • 앱 이름 입력: ZeroPack Social (또는 원하는 이름)
  • 생성 후 App Settings → Keys and Tokens 탭 클릭
Step 1-2 — 4개의 키 복사
아래 4개를 복사해서 어딘가에 메모해두세요 (나중에 GitHub Secrets에 입력)
TWITTER_API_KEY → API Key TWITTER_API_SECRET → API Key Secret TWITTER_ACCESS_TOKEN → Access Token TWITTER_ACCESS_TOKEN_SECRET → Access Token Secret
Step 1-3 — 쓰기 권한 설정 (중요!)
  • App Settings → User authentication settings → Edit 클릭
  • App permissions: Read and write 선택
  • 저장 후 Access Token을 재발급 (기존 토큰은 쓰기 권한 없음)
주의: 쓰기 권한 변경 후 반드시 Access Token을 재발급해야 합니다. 기존 토큰으로는 포스팅이 실패합니다.

LinkedIn API 설정
소요 시간: 약 15분 | linkedin.com/developers | 토큰 60일 유효
주의: LinkedIn Access Token은 60일마다 갱신이 필요합니다. 아래 Step 2-4에서 자동 갱신 방법을 설명합니다.
Step 2-1 — 앱 생성
  • linkedin.com/developers/apps/new 접속
  • App name: ZeroPack, LinkedIn Page: 본인 프로필 또는 회사 페이지
  • 앱 생성 후 Products 탭 → Share on LinkedIn 신청 (즉시 승인)
Step 2-2 — OAuth 2.0 Access Token 발급
  • Auth 탭 → OAuth 2.0 tools 클릭
  • Scopes: openid, profile, w_member_social 체크
  • Request access token → 로그인 승인 → 토큰 복사
LINKEDIN_ACCESS_TOKEN → 발급된 access_token 값
Step 2-3 — Person ID 확인
  • 아래 API를 브라우저에서 직접 호출 (발급한 토큰 붙여넣기)
https://api.linkedin.com/v2/userinfo 헤더: Authorization: Bearer {LINKEDIN_ACCESS_TOKEN} → 응답의 "sub" 값이 LINKEDIN_PERSON_ID 입니다
Tip: Postman 또는 브라우저 개발자도구 Network 탭에서 호출하거나, curl 명령어로 확인 가능.
Step 2-4 — 60일 토큰 갱신 알림 설정
LinkedIn 토큰은 60일마다 수동 갱신 필요. GitHub Actions가 실패하면 이메일 알림이 오므로 그때 재발급하면 됩니다.
  • GitHub → Settings → Notifications → Actions: Failed workflows only 이메일 알림 켜기
  • 포스팅 실패 이메일 오면 Step 2-2 반복 후 GitHub Secret 업데이트
3
Threads API 토큰 발급
소요 시간: 약 10분 | developers.facebook.com | 토큰 60일 유효 (자동 갱신 가능)
Step 3-1 — Meta 개발자 앱 생성
  • developers.facebook.com/apps 접속 → 앱 만들기
  • 앱 유형: 기타 → 앱 이름: ZeroPack
  • 좌측 메뉴 → Threads API → 설정 클릭
Step 3-2 — Access Token 발급
  • Threads API → Threads 사용자 토큰 생성기 클릭
  • Threads 계정으로 로그인 → 권한 승인
  • 생성된 Short-lived token 복사
  • 아래 명령어로 Long-lived token (60일)으로 교환:
https://graph.threads.net/access_token ?grant_type=th_exchange_token &client_secret={앱_시크릿} &access_token={SHORT_LIVED_TOKEN} → 응답의 access_token = THREADS_ACCESS_TOKEN
Step 3-3 — User ID 확인
https://graph.threads.net/v1.0/me?access_token={THREADS_ACCESS_TOKEN} → 응답의 "id" 값 = THREADS_USER_ID
4
GitHub Secrets 입력
소요 시간: 약 5분 | github.com/hiwebcorgi/zp-pages/settings/secrets/actions
입력할 Secrets 목록 (총 8개)
Secret 이름값 출처플랫폼
TWITTER_API_KEY developer.twitter.com → API Key Twitter
TWITTER_API_SECRET developer.twitter.com → API Key Secret Twitter
TWITTER_ACCESS_TOKEN developer.twitter.com → Access Token Twitter
TWITTER_ACCESS_TOKEN_SECRET developer.twitter.com → Access Token Secret Twitter
LINKEDIN_ACCESS_TOKEN linkedin.com/developers → OAuth 2.0 Tools LinkedIn
LINKEDIN_PERSON_ID /v2/userinfo API 응답의 "sub" 값 LinkedIn
THREADS_ACCESS_TOKEN Meta 개발자 → Long-lived token Threads
THREADS_USER_ID graph.threads.net/v1.0/me 응답의 "id" Threads
입력 방법
  • github.com/hiwebcorgi/zp-pages/settings/secrets/actions 접속
  • New repository secret 클릭
  • Name: 위 표의 Secret 이름 입력 / Secret: 해당 값 붙여넣기
  • 위 과정을 8개 반복

테스트 실행
소요 시간: 2분 | 수동으로 워크플로우 실행해서 정상 동작 확인
  • github.com/hiwebcorgi/zp-pages/actions/workflows/social-post.yml 접속
  • Run workflow 버튼 클릭 → Run workflow 확인
  • 실행 완료 후 로그 확인: ✅ Twitter 발행 완료, ✅ LinkedIn 발행 완료, ✅ Threads 발행 완료
  • 각 SNS 계정에서 실제 게시물 올라갔는지 확인
Tip: 테스트 시 schedule.json에서 오늘 날짜로 된 항목이 없으면 "오늘 예약된 포스팅 없음"으로 종료됩니다. 테스트용으로 오늘 날짜 항목을 추가하거나, 기존 항목의 date를 오늘로 임시 수정 후 테스트하세요.
